# 基础命令
## 首次使用
1.初始化本地仓库
使用`cd`命令进入我们要建git仓库的文件夹目录下，输入
```Bash
git init
```
如果执行完后这个文件夹里多出来一个.git文件夹，说明本地仓库初始化完成。

2.将所有文件添加到暂存区
在这个目录下，输入
```Bash
git add .
```
这一步告诉 Git，你准备好要提交当前目录下的所有变动了（`.` 代表当前目录下的所有文件，比如`code .`就是用vscode打开当前目录下的所有文件）

可以随时使用 `git status` 命令来查看当前哪些文件处于暂存区，这是一个很好的确认习惯

3.提交更改
仍然是在这个目录下，输入
```Bash
git commit -m "balabala"
```
这里的balabala代指提交信息，用来说明这次提交更改了哪些东西，比如这是我们第一次提交，可以说`git commit -m "git桑，首次使用请多关照:)"`

## github远程同步

4.关联 GitHub 远程仓库
在敲代码前，需要先在 GitHub 网页端建一个没有任何文件（不要勾选自动生成 README 等）的空仓库。创建好后复制它的链接(这里我用`https://github.com/你的用户名/你的仓库名`来指代它)，在当前目录下，输入：

```Bash
git remote add origin https://github.com/你的用户名/你的仓库名.git

```

这一步是给本地仓库指条明路，告诉它该往哪里同步。`origin` 只是给后面那长长的一串远程网址起的一个本地代号，方便以后叫它。

5.重命名分支并推送
接着输入：

```Bash
git branch -M main

```

`-M`是强制重命名的命令，`git branch -M main`就是把当前所在分支强行重命名为main。之所以这么做，这是因为老版 Git 默认的主分支叫 `master`，而 GitHub 现在默认的主分支叫 `main`，为了向人家看齐，我们要把本地的分支名字也换成 `main`。分支是git的一个很好用的功能，想了解更多关于分支的事，请看[[#分支]]

最后，在这个目录下输入：

```Bash
git push -u origin main

```

这就把本地的代码正式推送到 GitHub 上了。这里的 `-u` 是个一劳永逸的好参数，意思是把本地的 `main` 和远程的 `main` 建立死绑关系。以后再提交，就不用敲这么长了。

## 日常提交同步三步走

完成上面的首次配置后，以后如果你在这个文件夹里有了新的改动，想要提交到git并同步到云端，只需要简单粗暴的三个命令：

1. 添加到暂存区
还是在这个目录下，输入：

```Bash
git add .

```

2. 提交更改
输入：

```Bash
git commit -m "比如：更新了STM32核心板的晶振电路"

```


3. 同步到github
输入：

```Bash
git push

```

因为之前首次推送时加过 `-u` 绑定了目标，所以这里直接敲 `git push` 就行，系统会自动把你刚才打包好的改动，稳稳地传到 GitHub 上对应的仓库里。


# 分支

Git 的核心功能之一就是分支，这个功能允许你在本地仓库开出多个“平行宇宙”。

举个例子：当你文章写到一半或者代码敲到一半时，突然涌现出一个新思路，它也许通往天堂，也许通往地狱，但不管怎样，你都想尝试一下。为了避免可能会让文件面目全非的新思路。这时你可以新建一个分支去放飞自我。如果搞砸了，直接切回主分支，就当一切没发生过，文件瞬间恢复原样；如果写得很好，再把它合并回主分支。这就是分支带来的“安全存档”机制。

### 1. 新建分支
假设我们要新建一个叫 `dev`（通常代表 development 开发）的分支，在当前目录下输入：

```Bash
git branch dev

```

这会在本地默默建好一个名为 `dev` 的分支。但注意，执行完后你本人依然停留在原来的 `main` 分支上，并没有走过去。

### 2. 切换分支
要把你的工作区切换到刚刚建好的 `dev` 分支，输入：

```Bash
git switch dev

```

（注：网上很多老教程会教你用 `git checkout dev`，但 `checkout` 这个词既能切分支又能恢复文件，容易让人搞混。新版 Git 推荐用更直观的 `switch`。）

### 3. 新建并直接切换（日常最常用）
平时干活为了省事，通常不会建完再切，而是把两步并作一步，直接新建并切过去：

```Bash
git switch -c dev

```

这里的 `-c` 代表 create，相当于一条龙服务，非常实用。

### 4. 切换回主分支
当你在分支上折腾完，想要回到主线时，只需要输入：

```Bash
git switch main

```

一敲回车，你会发现你电脑里的文件就像变魔术一样，瞬间变回了你离开 `main` 分支时的样子。

### 5. 合并分支
如果你在 `dev` 分支里尝试的新思路大获成功，你想把它正式纳入主线代码里。首先，你需要先使用`git switch main`切回主分支，然后，在主分支下输入：

```Bash
git merge dev

```

这一步就是把 `dev` 分支里的改动，全部吸收到当前的 `main` 分支里。合并完之后，你的主分支就包含了最新的心血了。

### 6. 查看分支

有时候开的“平行宇宙”太多，你会忘记自己到底建了哪些分支，或者忘了自己当前到底身处哪一个分支。这时候可以输入：

```Bash
git branch

```

这会列出你本地所有的分支。当前所在的分支前面会有一个 `*` 号，并且通常会高亮显示，告诉你“你现在就在这里”。
*(补充：如果想连着远程仓库（比如 GitHub/Gitee）上的分支一起看，可以加上 `-a` 参数：`git branch -a`)*

### 7. 删除分支

当你在 `dev` 分支上的新功能开发完毕，并且已经成功 `merge`（合并）到了 `main` 分支，这个 `dev` 分支的历史使命就完成了。为了保持分支列表的清爽，你可以把它删掉：

```Bash
git branch -d dev

```

这里的 `-d` 代表 delete。Git 很聪明，如果你用 `-d` 删除，它会帮你检查这个分支有没有被合并过。如果还没合并，它会报错阻止你，怕你丢失心血。
如果你确认这就是个废弃分支，里面的代码不要了，**铁了心要强行删除**，可以把小写换成大写：

```Bash
git branch -D dev

```

### 8. 重命名分支

假设你建了一个叫 `test` 的分支，后来发现这个名字太宽泛了，想把它改成 `login-feature`，只需要用到 `-m`（move/rename）指令：

```Bash
git branch -m test login-feature

```

如果你当前**已经身处**在这个想改名的分支上了，那就更简单了，直接省略旧名字：

```Bash
git branch -m login-feature

```

### 9. 解决合并冲突（Merge Conflict）

这不是一个单独的命令，而是合并分支时必经的“小磨难”。
并不是所有的 `git merge` 都能顺风顺水。假设你在 `dev` 分支修改了 `A.txt` 的第一行，而在 `main` 分支里，你也（或者你的同事）修改了 `A.txt` 的第一行。当你尝试合并时，Git 就懵了：“这两个平行宇宙里，同一份文件的同一个地方被改成了不同样子，我该听谁的？”
这时候 Git 会暂停合并，并提示 **Conflict（冲突）**。

你需要：

1. 打开那个有冲突的文件，Git 已经在里面用 `<<<<<<<`、`=======`、`>>>>>>>` 给你标出了两边的不同内容。
2. 手动把这些标记删掉，保留你最终真正想要的内容。
3. 重新执行 `git add A.txt` 和 `git commit -m "解决合并冲突"`，合并就正式完成了。

### 10. 分支变基（Rebase - 进阶魔法）

除了 `git merge`，Git 还有另一种合并分支的方式叫 `rebase`（变基）。
`merge` 会在历史记录里保留分支分叉和汇合的轨迹；而 `rebase` 就像拥有“篡改时间线”的能力，它会把你 `dev` 分支上的修改，强行“剪切”并“粘贴”到 `main` 分支的最顶端，让整个代码的历史记录变成一条毫无分叉的直线，非常强迫症友好。

如果你在 `dev` 分支上，想把主分支的内容变基过来，可以输入：

```Bash
git rebase main

```

*(注：新手前期建议先用熟练 `merge`，等遇到团队协作对代码提交历史有“直线要求”时，再去折腾 `rebase`。)*

### 11. 推送本地分支到远程（与云端联动）

刚才的所有操作都是在你电脑本地的“自嗨”。如果你想把这个新建的 `dev` 分支推送到远端的 GitHub/Gitee 上和别人共享，可以直接推送：

```Bash
git push -u origin dev

```

这里的 `-u`（等同于 `--set-upstream`）是给本地的 `dev` 分支和远程的 `dev` 分支牵一根“红线”绑定起来。以后你在 `dev` 里再提交代码，直接敲 `git push` 就可以了。
